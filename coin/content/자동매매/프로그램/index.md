코인 자동매매 프로그램은 시세를 읽고, 사람이 정한 조건과 비교하고, 조건이 맞으면 주문을 보낸 뒤 결과를 기록한다. 새벽마다 차트를 확인하는 일을 줄이려면 먼저 이 네 단계 가운데 어디까지 자동화할지 정하면 된다.

## 프로그램은 네 단계를 반복한다

첫 단계는 시세 조회다. 프로그램은 거래소 API에서 현재가나 봉 데이터를 받아온다. 조건에 이동평균선이나 RSI를 쓴다면 필요한 기간의 가격도 함께 읽는다. 조회 간격은 규칙의 시간 단위와 맞춰야 한다. 일봉 마감 조건이라면 매초 같은 계산을 되풀이할 이유가 없다.

둘째는 조건 판단이다. 받은 가격으로 지표를 계산하고 ‘참’ 또는 ‘거짓’으로 판정한다. ‘짧은 이동평균선이 긴 이동평균선을 아래에서 위로 통과했다’처럼 이전 값과 현재 값을 함께 봐야 하는 규칙도 있다. ‘봉 마감 시마다 한 번’처럼 판정 시점까지 적어야 같은 봉에서 주문이 반복되지 않는다.

셋째는 주문이다. 프로그램은 주문 방향, 주문 종류, 가격, 수량을 구성해 거래소 API로 보낸다. 넷째는 기록이다. 판정 시각, 사용한 시세, 조건 결과, 주문 요청과 응답을 남긴다. 그래야 사람이 나중에 규칙이 어떤 순서로 실행됐는지 읽을 수 있다.

## 공식 기능으로 시작할 수 있는 일

일정한 금액을 정해진 주기로 사는 일은 거래소 공식 기능으로 시작할 수 있다. 업비트 ‘코인 모으기’는 비트코인·이더리움·엑스알피·솔라나 중 하나를 고르고 최소 1만 KRW부터 최대 100만 KRW까지 금액과 매일·매주·매월 주기를 설정하는 기능이다(2026년 9월 확인 기준). PC웹과 모바일 앱에서 이용할 수 있다.

공식 기능은 입력 항목이 이미 마련돼 있어 코드를 작성하지 않아도 된다. 원하는 규칙이 ‘정한 코인을 정한 금액과 주기로 산다’라면 이 범위 안에서 설정을 끝낼 수 있다. 가격 구간이나 지표 조건처럼 화면에 없는 판단식을 넣으려면 API 프로그램으로 넘어간다.

## API로 만들면 달라지는 것

API 방식에서는 프로그램이 거래소와 직접 요청을 주고받는다. 업비트는 Access Key와 Secret Key로 서명한 JWT를 인증에 쓰고, 빗썸 Private API도 JWT 인증 토큰을 요구한다. 키 발급, 허용 IP 등록, 인증 토큰 생성이 프로그램의 시작 부분이 된다.

그다음에는 조건을 코드로 옮긴다. 예를 들어 시세를 읽어 두 이동평균선을 계산하고, 교차가 봉 마감 뒤 확인됐을 때만 주문 함수를 부른다. 트레이딩뷰 얼러트를 조건 확인에 쓸 수도 있다. 트레이딩뷰는 가격이나 지표 조건이 성립했을 때 알림, 이메일, 웹훅 URL 등으로 알릴 수 있다. 웹훅은 지정한 URL로 POST 요청을 보낸다.

API는 조건의 모양을 직접 정할 수 있다는 점이 핵심이다. 대신 주문을 한 번만 낼 조건, 기록 항목, 프로그램을 실행할 시간도 사람이 코드로 정한다.

## 프로그램을 고르는 기준

첫 기준은 규칙을 그대로 입력할 수 있는가다. 정기 매수라면 공식 기능의 코인·금액·주기가 내 문장과 맞는지 본다. 그리드라면 가격의 위아래 범위, 칸의 수, 칸마다 쓸 금액을 입력할 수 있어야 한다. 시그널 방식이라면 지표 종류, 기간, 기준값, 봉 마감 조건을 적을 수 있어야 한다.

둘째는 거래소의 공식 인증을 쓰는가다. 주문 권한이 있는 키는 허용 IP를 등록해 사용한다. 셋째는 기록을 남기는가다. 시세, 판정, 주문 요청, 거래소 응답이 시각과 함께 보여야 규칙을 점검할 수 있다.

넷째는 주문 종류가 규칙과 맞는가다. 업비트 주문 생성 API는 지정가, 시장가 매수, 시장가 매도, 최유리 지정가를 지원한다(2026년 9월 확인 기준). 내가 작성한 규칙이 가격을 지정하는지, 금액이나 수량을 입력하는지에 따라 알맞은 주문 형식이 달라진다.

## 프로그램에 넣을 설정값

설정은 세 묶음으로 정리하면 읽기 쉽다. 거래 설정에는 코인, 매수·매도, 주문 종류, 한 번의 금액이나 수량을 넣는다. 신호 설정에는 지표, 계산 기간, 기준값, 봉 간격과 판정 시점을 넣는다. 운영 설정에는 시작일, 종료일, 실행 시간, 같은 신호의 재주문 간격, 기록 위치를 넣는다.

설정을 문장과 값으로 함께 보관하면 코드를 고칠 때 기준이 생긴다. 신호별 실측 페이지를 참고할 때도 실측에 쓰인 신호 문장과 내 프로그램의 판정 문장이 같은지 먼저 대조할 수 있다.

## 처음 한다면 이 순서로

1. 자동화할 규칙을 ‘언제, 무엇을, 얼마만큼 주문한다’는 문장으로 쓴다.
2. 업비트 ‘코인 모으기’처럼 공식 기능의 입력 항목으로 끝낼 수 있는지 확인한다.
3. 직접 만든 조건이 필요하면 거래소 공식 API와 인증 방식을 고른다.
4. 시세 조회, 조건 판단, 주문, 기록을 각각 나눠 한 단계씩 확인한다.
5. 주문 기록을 읽고 중복 주문을 막는 판정 시점을 정한다.

## 책에서 이어지는 것

‘제8장 그래서 차트를 어디에 씁니까’는 신호의 방향보다 금액과 실행 기준을 먼저 정하는 법을 설명한다. 프로그램에 넣을 주문 금액, 멈출 가격, 실행 여부를 문장으로 다듬을 때 이어서 볼 수 있다.
