업비트 자동매매는 정기 매수라면 공식 ‘코인 모으기’로, 가격이나 지표 조건까지 직접 정하려면 Open API로 시작한다. 먼저 원하는 규칙이 금액과 주기만으로 끝나는지 확인하면 두 방법 가운데 하나를 고르기 쉽다.

## 코인 모으기로 정기 매수하기

‘코인 모으기’는 업비트가 제공하는 공식 자동 적립 기능이다. 비트코인·이더리움·엑스알피·솔라나 중 매수할 코인을 고르고, 원하는 금액과 주기를 설정한다. 금액은 최소 1만 KRW부터 최대 100만 KRW이며, 주기는 매일·매주·매월 가운데 선택한다(2026년 9월 확인 기준).

PC웹과 모바일 앱에서 이용할 수 있다. 규칙은 ‘선택한 코인을 정한 주기마다 정한 금액으로 산다’로 정리된다. 지표 계산이나 주문 코드를 작성하지 않고 정기 적립을 시작하려는 경우에 맞는다.

사람이 정할 값은 코인, 한 번의 금액, 주기와 실행 기간이다. 매수 기록을 확인할 날짜도 함께 정하면 설정과 실제 주문을 같은 표에서 대조할 수 있다.

## Open API 키 발급과 허용 IP

직접 만든 조건으로 주문하려면 업비트 PC 웹에 로그인한 뒤 ‘마이페이지 > Open API 관리’에서 API 키를 발급한다. 계정당 메인포켓 기준 최대 10개까지 발급할 수 있고, 서브포켓은 포켓당 최대 5개까지 발급할 수 있다(2026년 9월 확인 기준).

발급받은 Access Key와 Secret Key는 인증 토큰을 만드는 데 쓴다. 주문하기·출금하기 API를 이용하려면 허용 IP를 등록한다. 주문 권한 키는 프로그램을 실행하는 서버의 허용 IP와 묶어 사용한다. 한 키에 등록할 수 있는 허용 IP의 최대 개수는 공식 문서에서 확인된 수치가 없으므로 숫자로 정하지 않는다.

프로그램에서는 키 값을 코드 문장 안에 직접 적기보다 실행 환경에서 읽도록 구성할 수 있다. 기록에도 Access Key, Secret Key, 완성된 JWT를 남기지 않고 주문 식별값과 응답 결과만 구분해 둔다.

## JWT로 요청 인증하기

업비트 Open API 인증은 JWT를 쓴다. Access Key와 Secret Key로 JWT 토큰을 서명하고 `Authorization: Bearer {JWT 토큰}` 헤더에 담아 요청한다. 서명 알고리즘은 HS256을 권장한다.

JWT 페이로드에는 `access_key`와 매 요청마다 새 UUID로 만드는 `nonce`가 들어간다. 요청 파라미터가 있으면 `query_hash`와 `query_hash_alg`도 포함한다. REST API와 웹소켓 연결 요청에 같은 인증 방식이 적용된다.

순서는 요청 파라미터 준비, 파라미터 해시 계산, 페이로드 작성, Secret Key로 서명, Authorization 헤더 추가다. 시세처럼 인증 없이 조회하는 요청과 계좌·주문처럼 인증이 필요한 요청은 함수부터 나누면 구조가 선명해진다.

## 주문 종류와 입력값

업비트 주문 생성 API는 네 가지 주문 형식을 지원한다(2026년 9월 확인 기준). 지정가 `limit`는 `price`와 `volume`을 입력한다. 시장가 매수 `price`는 `price`를 입력하고 `volume`은 입력하지 않는다. 시장가 매도 `market`은 `volume`을 입력하고 `price`는 입력하지 않는다.

최유리 지정가 `best`는 `time_in_force`에 `ioc` 또는 `fok`를 입력한다. 자동매매 규칙을 만들 때 ‘시장가로 산다’처럼 이름만 쓰지 말고, 매수 금액을 넣는지 매도 수량을 넣는지까지 주문 문장에 적어야 한다.

지정가는 주문 가격과 수량을 계산하는 단계가 필요하다. 시장가 매수는 쓸 금액을, 시장가 매도는 팔 수량을 계산한다. 프로그램은 조건 판단 결과와 주문 형식에 맞는 필드를 만든 뒤 요청한다.

## 요청 수에 맞춰 실행 간격 정하기

주문 API 요청 수는 초당 최대 12회, 주문 테스트는 초당 최대 8회다. 전체 주문 취소는 2초당 최대 1회이며, 잔고조회·주문조회·입출금 등을 포함한 일반 API는 초당 최대 30회다(2026년 9월 확인 기준).

프로그램의 반복 간격은 이 수치 안에서 정한다. 한 번의 규칙 판정에서 시세 조회, 잔고 조회, 주문 테스트, 실제 주문을 각각 몇 번 부르는지 먼저 세면 된다. 같은 봉에서 조건이 계속 참일 때는 주문 완료 여부를 기록하고 다음 판정에서 확인해 중복 요청을 줄인다.

## 처음 한다면 이 순서로

1. 금액과 주기만 정하면 되는지 보고, 맞으면 ‘코인 모으기’를 설정한다.
2. 직접 만든 조건이 필요하면 PC 웹의 ‘마이페이지 > Open API 관리’에서 키를 발급하고 허용 IP를 등록한다.
3. JWT 인증과 시세 조회를 연결한 뒤 조건 판단 함수를 붙인다.
4. 주문 테스트로 요청 형식을 확인하고 주문 종류에 맞는 금액·수량 필드를 정한다.
5. 주문 응답을 기록하고 API별 요청 수 안에서 반복 간격을 설정한다.

## 책에서 이어지는 것

API가 실행할 주문 금액과 멈출 가격을 정하는 기준은 ‘제8장 그래서 차트를 어디에 씁니까’에서 이어진다. 차트를 방향 예측보다 금액과 실행 여부를 정하는 도구로 쓰는 방법을 프로그램 규칙에 옮길 수 있다.
